## Current Architecture

### Data Structure

Each family member record contains:

```javascript
{
  id: string,           // Unique identifier
  name: string,         // Full name
  birthDate: Date,      // Birth date
  deathDate: Date,      // Death date (optional)
  gender: 'male'|'female',
  imageUrl: string,     // Photo (base64 or URL)
  notes: string,        // Stories and memories

  // Relationship fields (ONLY these are stored)
  childIds: string[],   // Array of children IDs
  spouseId: string,     // Spouse ID
  parentId: string,     // Shared parent ID (for sibling grouping)

  // Special fields
  root: boolean,        // Root user status
  createdAt: Date,
  updatedAt: Date
}
```

### Root User Logic ⭐

**Critical business rules:**

1. **First User**: Gets `root: true` automatically
2. **Parent Addition**: First parent added to root user takes over root status, original becomes `root: false`
3. **Male Spouse Rule**: Male spouse added to root user takes over root status, original becomes `root: false`
4. **Sibling Inheritance**: Siblings of root users inherit `root: true` status
5. **Children**: Always get `root: false` (no inheritance)
6. **Spouse**: Always get `root: false` (except male spouse takeover rule)

## Relationship Management Rules

### Adding Relationships

**Sibling Rules:**

- Only root users can have siblings added
- Non-root users: sibling option disabled, must link to parent instead
- Siblings inherit `root: true` from root users
- Creates shared `parentId` if needed

**Parent Rules:**

- If linked member already has parents: new person becomes spouse of first parent
- Otherwise: normal parent relationship created
- Parents always get `root: true`, children lose `root: false`

**Child Rules:**

- Can only add children if user has a spouse (validation enforced)
- Child added to both parents' `childIds` arrays
- Children always get `root: false`

**Spouse Rules:**

- Bidirectional relationship (both get each other's ID)
- Male spouses of root users take over root status
- Female spouses always get `root: false`

### Path Finding Algorithm

**Priority Order for Navigation:**

1. **Children** (from `childIds`)
2. **Siblings** (same `parentId` OR shared parent via `childIds`)
3. **Parents** (who have person in their `childIds`)
4. **Spouses** (from `spouseId`)

Uses BFS algorithm to find shortest path with relationship prioritization.

## Family Tree Business Logic Summary

The application implements sophisticated family relationship rules that mirror real-world family dynamics:

- **Hierarchical Structure**: Root users anchor family trees
- **Natural Inheritance**: Root status flows to siblings, not children
- **Spouse Integration**: Male spouses can take leadership, females integrate
- **Parent Precedence**: First parents establish family structure
- **Child Protection**: Children cannot become roots, maintaining hierarchy
- **Navigation Logic**: Path finding prioritizes direct relationships

This creates an intuitive family tree system where users can build complex multi-generational family structures while maintaining logical relationship hierarchies.
